# Expert Chatbots: Multi-Agent AI Debate System

This project is a web application that allows two artificial intelligence models to impersonate real academic experts and debate a user-selected topic. The user specifies two experts, a topic, the number of messages in the conversation, and the delay between responses. Once the conversation begins, the system alternates responses between two AI models so that they simulate a structured academic discussion. Each AI model is instructed to respond as the chosen expert and to support claims with references to real scholarly work authored or cited by that expert. The goal of the project is to demonstrate how multiple AI agents can interact in a controlled loop to produce a structured dialogue that resembles an academic debate.

To use the application, the user first enters the names of two experts and a topic for discussion. The interface then allows the user to validate the experts before starting the conversation. The user can also set how many messages the debate should contain and how many seconds should pass between responses. When the conversation begins, the application displays each response in a transcript area, labeling which model produced the message. A visual indicator shows which model is currently generating a response, and a countdown timer shows when the next message will appear. The user also has the option to “jump in” and add a comment or question during the delay period, after which the conversation resumes.

One feature I am particularly proud of is the conversation loop that coordinates the two AI models. Instead of generating a single response, the system alternates between the models in a structured loop that continues until the selected number of turns has been reached. This makes the system behave like a multi-agent simulation rather than a standard chatbot. Another feature I am proud of is the interactive interface, which includes visual indicators showing which model is currently responding, a countdown timer between turns, and the ability for a user to intervene in the conversation. These features make the debate easier to follow and provide a more engaging user experience.

The project is deployed using Vercel, a cloud platform that allows web applications to be hosted and run serverless functions. The repository is connected to Vercel so that whenever the code is pushed to GitHub, Vercel automatically redeploys the application. Vercel serves the static front-end files such as the HTML, CSS, and JavaScript directly to users’ browsers, while also running the API files in the `api` folder as serverless functions. When the browser sends a request to `/api/openaiChat` or `/api/claudeChat`, Vercel executes the corresponding serverless function on its infrastructure and returns the response to the client. This allows the application to securely communicate with external AI APIs without exposing secret keys in the browser.

The project can also be run locally using a simple development server. After cloning the repository, the user installs dependencies with `npm install`. The application can then be started locally using `npm run dev` or another local server command. Once running, the site can be opened in a browser at `http://localhost` or the address provided by the development server. The API endpoints used by the application require secret API keys from the AI providers, which must be stored in environment variables rather than in the source code. For local development, these keys can be stored in a `.env` file that is not committed to the repository. When deploying the application to Vercel, the same variables must be added through the Vercel environment variable settings so the serverless functions can access them securely.

The repository is organized so that the front-end interface and the serverless API functions are clearly separated. The `index.html` file provides the main user interface of the application. It contains the form fields where users enter the expert names, topic, number of messages, and delay between responses. It also contains the transcript area where the conversation appears, the controls that allow the user to start the conversation, and the visual indicators that show which AI model is currently responding.

The `styles.css` file defines the visual design of the interface. It controls the layout, spacing, typography, and colors used in the application. It also defines the styling for conversation messages and the animated pulsing dots that indicate when a model is generating a response.

The `script.js` file contains the primary client-side logic of the application. It reads user input from the interface, manages the conversation loop, sends prompts to the API endpoints, receives AI responses, and updates the transcript on the page. It also controls the countdown timer, the model activity indicators, and the jump-in feature that allows a user to add a message during the conversation.

The `api/openaiChat.js` file is a serverless function responsible for communicating with the OpenAI API. It receives a prompt from the front-end, sends that prompt to the OpenAI chat completion endpoint, and returns the generated response back to the browser. This function ensures that the API key is kept on the server side and is never exposed to the client.

The `api/claudeChat.js` file performs the same role for the Anthropic Claude API. It receives prompts from the front-end, sends them to the Anthropic messages endpoint, and returns the generated response to the application so the debate can continue.

The `api/checkExperts.js` file validates the expert names entered by the user before the conversation begins. It performs checks to ensure that the inputs are not empty and may also call an AI model to determine whether the names correspond to recognizable academic experts. This helps prevent the conversation from starting with invalid inputs.

Overall, this project demonstrates how multiple AI systems can be coordinated through a structured loop to simulate a discussion between experts. By combining a browser interface, serverless functions hosted on Vercel, and external AI APIs, the application creates a simple but powerful example of a multi-agent AI interaction system.
